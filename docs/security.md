# Goビルドと配布時のセキュリティ対応

## eMudhra中間CA秘密鍵漏えい（2026-10-21確認）

[Go公式告知](https://groups.google.com/g/golang-announce/c/66pojueaQek)では、
CVE-2026-111943への対策としてGo 1.27.3 / 1.26.10が公開されている。
`crypto/x509`は漏えいした中間CAを含む証明書チェーンを拒否する。
背景は[インシデントの説明](https://emudhra.we-have-a-problem.com/)を参照。

renstiqはGitHub APIと自己更新ファイルの取得にGoのHTTPSクライアントを使う。
v0.6.4の配布済みLinux amd64バイナリはGo 1.25.0でビルドされており、
Goの今回の対策を含まない。

このリポジトリの`go.mod`は最低要件をGo 1.27.3に設定する。
テストとリリースの`actions/setup-go`はこの値からビルド用Goを選択し、
リリース時には各バイナリに記録されたGoバージョンが指定値と一致することを
アーカイブ作成・アップロード前に検証する。
ローカルでもGo 1.27.3以降を使用する。`go.mod`の変更やOSのCA更新だけでは、
既に配布・インストールされたバイナリは更新されない。

## 再ビルドと再配布

1. 修正を取り込み、通常のrelease-pleaseの手順でv0.6.4より新しいバージョンを準備する。
2. Go 1.27.3以降の対策を含むGoで、Linux/macOS × amd64/arm64の4配布物を再ビルドする。
   リリースのビルド情報検証と4アーカイブのチェックサム生成が成功したことを確認して公開する。
3. 利用環境のバイナリを新リリースに更新する。ソースから利用する場合も対策済みGoで
   `go install .`を実行して再ビルドする。
4. 対策済みGoでインストール済みバイナリのビルド情報を確認する。

   ```sh
   go version -m "$(command -v renstiq)"
   ```

   先頭行が`go1.27.3`、またはその対策を含む後続版であることを確認する。
   Go 1.26系列の既存ビルドを評価する場合の対策版は1.26.10以降だが、
   このリポジトリのビルド要件は1.27.3以降とする。

新リリースが公開されるまで、v0.6.4に対する`renstiq update`の「最新」表示は
今回の対策が適用済みであることを意味しない。既存のv0.6.4の資産を上書きせず、
新しいバージョンとして再配布する。配布ファイルの取得には、対策済みのブラウザや
CA/証明書検証が更新されたクライアントを使用し、証明書検証を無効にしない。
